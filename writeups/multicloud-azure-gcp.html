Multi-cloud resiliente: fallbacks entre Azure e GCP

  • Azure App Service
  • GCP Firestore
  • Node.js
  • Docker · ACI
  • 20/20

Resumo: a plataforma CityGuards corre em Azure com os dados no GCP Firestore. Quando um serviço falha ou fica caro demais, há sempre uma alternativa que mantém a aplicação a funcionar. Custo final: cerca de 72 € por mês.

O desafio

Uma plataforma de reporte cívico e gestão de ocorrências municipais tem de continuar disponível quando um fornecedor cloud falha, e proteger os dados dos cidadãos de acordo com o RGPD.

As decisões de engenharia

  • Persistência desacoplada. A meio do projeto, os créditos de estudante do Azure Cosmos DB esgotaram-se. Em vez de um problema, foi uma oportunidade: migrei a camada NoSQL para o Google Cloud Firestore, mantendo o frontend e a API no Azure App Service e os uploads no Azure Blob Storage.
  • Transações atómicas (db.runTransaction). Os pontos de gamificação e o resgate de vouchers são alterados dentro de transações no Firestore, para evitar race conditions com muitos pedidos em simultâneo e manter os dados de cada município isolados.
  • Degradação graciosa.
    • Se o Azure AI Vision atingir a quota ou ficar lento, o backend usa um classificador local (TextHeuristicFallback) baseado em padrões de texto, e o cidadão consegue submeter na mesma.
    • O serviço de PDFs em Azure Container Instances só corre quando é preciso, para poupar custos. Se o contentor estiver parado, o PDF é gerado diretamente no Node.js.
  • Soberania de dados. Analisámos a compatibilidade entre guardar dados de cidadãos na UE e o acesso extraterritorial permitido pelo US CLOUD Act a fornecedores com sede nos EUA.

Resultado

Projeto de equipa (Diogo Oliveira, Rafael Cruz, Tiago Alves), orientado pelo Prof. Osvaldo Santos, com classificação final de 20/20. A minha parte: backend Node.js/Express, migração para Firestore com transações atómicas e o serviço de PDFs em Docker.

Resilient multi-cloud: fallbacks across Azure and GCP

  • Azure App Service
  • GCP Firestore
  • Node.js
  • Docker · ACI
  • 20/20

TL;DR: the CityGuards platform runs on Azure with its data on GCP Firestore. When a service fails or gets too expensive, there is always a fallback that keeps the app working. Final cost: about €72 per month.

The challenge

A civic reporting and municipal incident platform has to stay available when a cloud provider fails, and protect citizens' data in line with the GDPR.

Engineering decisions

  • Decoupled persistence. Midway through the project, our Azure Cosmos DB student credits ran out. Rather than a blocker, it became an opportunity: I migrated the NoSQL layer to Google Cloud Firestore, keeping the frontend and API on Azure App Service and uploads on Azure Blob Storage.
  • Atomic transactions (db.runTransaction). Gamification points and voucher redemptions change inside Firestore transactions, preventing race conditions under concurrent load and keeping each municipality's data isolated.
  • Graceful degradation.
    • If Azure AI Vision hits its quota or slows down, the backend switches to a local text-pattern classifier (TextHeuristicFallback), so citizens can still submit.
    • The PDF service on Azure Container Instances only runs when needed, to save cost. If the container is stopped, the PDF is generated directly in Node.js.
  • Data sovereignty. We analysed how storing EU citizens' data fits with the extraterritorial access the US CLOUD Act grants over US-based providers.

Outcome

Team project (Diogo Oliveira, Rafael Cruz, Tiago Alves), supervised by Prof. Osvaldo Santos, graded 20/20. My part: the Node.js/Express backend, the Firestore migration with atomic transactions, and the Docker PDF service.
